# 快速导入与多片段实况导出

## 最新交互修正（覆盖此前的多行设计）
- 用户明确纠正：始终只显示一条视频时间轴。「＋」在同一轨道上新增一组范围选择器，不新增时间轴或片段行。
- 共享唯一刻度、缩略图和播放头；各组选区可重叠，点击范围/边界激活。完全重叠时用紧凑编号按钮切换，不拆成多条轨道。
- 保留每段独立封面、裁剪及独立文件导出。第 4 步原多行测试仅为历史结果；本次修正须重新做桌面回归。

## Context
- 用户希望导入视频后尽快播放、操作，避免等待全片索引；在时间轴附近用「＋」添加多个导出选区，从一个长视频生成多个实况照片文件。
- 项目为 Electron / React / TypeScript，原生 Rust Media Foundation/WASAPI 预览，FFmpeg 导出。
- 已发现主要阻塞：`prepareNativeMedia` 等待源索引、`index.mapNative` 全片原生映射以及音轨准备全部完成才返回。已有容器索引快路径，但仍需全片原生核验，因此仅优化读索引不足以消除等待。
- `Timeline.tsx` 当前仅支持一个 `ClipSelection`，拖动与键盘操作逻辑可复用。
- `NativeTimeline` 的 seek/play/step 均依赖完整映射；仅取消 UI 加载遮罩不够，需新增不依赖精确源帧编号的时间预览路径。
- `prepareNativeAudio` 对每个音轨执行 FFprobe 全轨扫描、原生全轨扫描，必要时再生成整轨 PCM；这也是普遍慢的原因，不能只处理视频索引。
- `MediaSession` 目前只有一个 cover/analysis/draft；新封面会释放旧封面，必须按片段隔离资源，不能只在前端保存多个封面 URL。
- 导出 `analyzeExport` / `renderExportDraft` 本来就从原片独立核实区间/PTS，不依赖完整预览索引，可复用而非等全片核验。

## Approach
### 已确认的体验
- 以用户描述的 AE / PR 导入体验为目标：直接使用原片、按需读取，不能只是把全片加载藏到后台。此处借鉴工作流，不声称复现 Adobe 私有实现。
- 将「可以看/剪」与「完整精确索引就绪」解耦；精确帧身份和最终导出不能靠估算。
- 用户最新明确：可以接受导入时几秒等待，但进入可用状态时必须画面、音频、播放、拖动都正常，不接受先静音播放再等声音；逐帧/封面/导出也应可发起操作，不等后台整片索引解锁。各类素材都慢，需要通用优化。
- 最新确认：「＋」从播放位置新增默认 3 秒选区，末尾收短，在同一条时间轴上增加范围选择器，可重叠、可删除。
- 已确认：每段独立封面与裁剪，共用画质/帧率/分辨率；支持导出当前段与全部独立文件。
- 已确认：特殊格式可明确回退并等待兼容准备，不承诺所有格式物理零耗时。
- 已确认：保留导入时整片初始选区；批量只选一次目录，按片段编号命名，不覆盖文件；普通单段失败继续其余，取消保留已成功文件。
- 进一步发现：Rust 已有按时间 `seek` / `locate` 与顺序 `read`，可复用做快速预览；现有 `encode-plan.ts` 已有只解码剪点附近、覆盖不足向前重试的算法，可提炼为局部精确帧解析。不可用平均帧率推算 PTS，也不可把少量抽检当作全片映射核验。
- 因音频需同时可用，快路径必须完成所选音轨的小范围实际解码与时间原点核对再宣布 ready；全轨扫描仅用于必要回退。

### 1. 改为按需媒体读取，不把整片核验搬到后台
1. **轻量打开**：复用首次 probe 结果，避免 `open` 与 `prepareNativeMedia` 重复探测；启动常驻原生解码器，解码首个可显示画面，准备所选音轨和时间原点。首帧/声音预检通过后才宣布可播放。无音轨素材正常静音；多音轨沿用明确选择策略，不偷偷选择或丢弃音轨。
2. **快路径不执行全片工作**：不等待 `buildFrameIndex`、`mapNative`、全轨 `sourceSummary/nativeSummary` 或整片转码。容器 sample/keyframe 信息是按需定位辅助，不作为完整验证证明；不能因现有容器优化不支持 VFR 或超过 100k 样本就直接要求全片扫描。容器辅助读取设预算，超预算先使用原生按时间定位。
3. **播放/拖动**：复用 Rust `seek/locate/read`、帧缓存及 WASAPI 时钟，顺序播放按实际帧时间推进，seek 只解码附近 GOP；明确处理 B 帧、edit list、视频起始偏移、音频前导延迟。对入点使用 at-or-after、出点使用 before，不拿最后一帧伪装边界命中。保留 epoch、latest-wins、ACK 背压及拖动后暂停语义。
4. **精确功能按需处理**：新增有界局部帧解析器，提炼 `encode-plan.ts` 的邻域扫描/向前扩大覆盖策略。逐帧、当前帧封面及精确剪点只核实当前邻域的源整数 PTS/时序，与实际显示的原生帧建立局部映射；缓存已验证区间，不能按平均 FPS 推算。快速显示帧带独立的原生时间戳/身份状态，未解析前不伪造 `sourceFrame`、`pts` 或全片 frameCount。捕获始终绑定已 ACK 的 frameId 与 epoch，解析失败不能保存相邻帧冒充当前帧；无法唯一对应时明确回退。
5. **声音**：直接按需解码所选音轨；用实际首批样本、轨道身份、源/原生时间原点校准启动，不再先算整轨样本总数。播放/seek 持续检查局部时间连续性与时钟错误。多轨身份不明、异常间隙/偏移或原生解码失败时走既有显式兼容策略，不通过静音降级宣布 ready。取消、暂停、切换片段时必须停止 WASAPI。
6. **缩略图**：只请求当前可见视口，去重并复用缓存；交互优先，旧视口任务可取消，不能为每条选区重复解码缩略图。长扫描不能占用前台原生 reader；本轮不默认后台执行全片扫描。
7. **兼容回退**：保留现有精确整片索引/SDR/PCM 准备，限用于无法安全按需工作的素材，并显示具体原因、进度和取消/重试。HDR 仍需用户确认；回退切换先暂停并使旧 epoch 失效，保留已编辑选区。元数据可用时允许改选区，但不把无法播放的状态称作“就绪”。
8. **安全与范围**：源文件变化使局部缓存失效；读者退出确认后才清理资源，沿用磁盘/内存预算及原生释放屏障。按需精确解析允许受控调用 FFmpeg（旧“就绪后绝不调用媒体工具”的规则需明确更新），不是每次 pointermove 启动进程。本轮不增加跨启动持久缓存，不引入第二套浏览器播放器。

### 2. 时间轴多片段
- 始终只有一条轨道，共享时间刻度、缩略图、缩放、平移及播放头；轨道内叠加每段独立范围选择器，当前段高亮。点击范围或拖动其边界即激活、暂停播放，侧栏显示其封面/裁剪。紧凑编号按钮用于重叠选区切换及删除，不新增片段行。
- 「＋ 添加片段」只添加，不立即导出：从当前播放位置起选 3 秒并激活，接近结尾收短；若恰好在 EOF，则选结尾最多 3 秒，避免零长度。允许重叠；按创建顺序编号，不随起点拖动重排。
- 导入保留整片第一段；至少保留一段（最后一段删除按钮禁用）。播放选段、全选、起止输入与逐帧操作作用于当前段；全选不修改其他段。
- 状态拆分为 `clips[] + activeClipId + sharedSettings`。每段保存稳定 ID、revision、选区、裁剪/比例锁、封面引用、封面适配/背景；音轨策略、画质、帧率、分辨率及输出模式共用。
- 新段默认完整画面、自动首帧封面，不复制别段自定义封面。未手选封面始终跟随该段实际导出首帧；手选封面保持独立，即使位于选段外也沿用现有独立封面语义并明确提示。
- “原画质（跟随原片）”模式仍不应用裁剪，保留每段手动裁剪数据，关闭该模式恢复；不改变现有模式承诺。

### 3. 片段资源与批量导出
- 主进程按 `assetId + clipId + revision` 管理片段封面/分析/草稿与资源生命周期；替换/删除仅释放对应片段，不能在切换当前段时撤销其他段资源。封面晚到响应、旧分析和旧保存请求必须被拒绝或丢弃。
- 保留「预览当前段 / 导出当前段」；新增「全部导出（N）」确认摘要（范围、共享参数、警告），选择一次输出目录，按创建顺序串行分析→编码→封面→封装→校验→发布。
- 批次冻结片段和参数快照。运行时锁定编辑/导入，保留取消；进度以 batchId、clipId、任务编号和阶段隔离。一次只保留当前输出的重型草稿，完成即释放，避免 N 份完整编码缓存累积。
- 输出为 `原文件名_片段01.jpg` 等独立实况照片，不是合并视频；主进程生成安全文件名，冲突追加后缀且最终发布仍原子无覆盖，渲染端不能传任意输出路径。
- 单段内容错误继续后续并汇总成功/失败；源文件变化、磁盘耗尽、目录失效、清理失败等全局错误停止批次，不能无限重复失败。取消后保留已发布文件、清理未发布临时文件；处理发布/取消竞态，已发布绝不误报为取消。
- 复用原导出与发布流程，实际剪点、声音、色彩、Motion Photo 元数据和回读校验不降低标准。不增加项目保存、多源素材混编、撤销系统或多视频并行编码。

## 执行结论（2026-11-06）

六步执行结束，不等于所有验收目标关闭。完整证据及失败→修复过程见 `docs/fast-import-multi-clips.md`：原生 fmt/严格 Clippy/11+8 Rust 测试、release 与应用重建；160 单元、104 完整集成及新增 PCM 专项、17 开发桌面通过。最终内部目录包通过 16 项适用桌面和四份真实素材各两次复测，源文件及包哈希未变。

首轮基线仅量了严格准备函数，并非完整桌面端到端旧版本对照。最终包快路径样本 1.52–1.87s；两份 PCM 音轨需明确兼容，6.28–6.90s，未达 5s 目标。实际测量均明确标注哈希预热/未控制缓存；缺少每类十次、30s/5min/30min 冷热矩阵、缺失的大文件/两小时输入、真实物理音画及手机/干净机器验证，未以历史 manifest、跳过或有限样本冒充通过。第 6 步完成的是执行与如实记录，不是将这些缺口豁免。

## Verification
### 性能和体验
- 计时从确认文件对话框开始，分别记录元数据、首帧呈现 ACK、音视频可播放、首次远距离 seek、逐帧/封面及导出分析耗时；应用引擎冷启动另记但不得从总耗时隐藏。
- 工程目标：在记录配置的 Windows 本地 SSD 基准机上，普通可原生解码 1080p/4K AVC/HEVC 素材导入到音视频可用争取 1–3 秒，P95 ≤5 秒；这是待实测验收目标，不是已达到或所有文件保证。30 秒、5 分钟、30 分钟素材分别测试，至少 10 次/类，并区分冷/热文件缓存。
- 架构硬指标：快路径 ready 前无全片视频/音轨解码，工作量不随片长线性增长；ready 后播放有声（有音轨且已选择）、拖动立即响应，逐帧/封面/导出无需等全片任务解锁。缓存外长 GOP seek 单独记录 P50/P95，不隐瞒必要解码延迟。
- 首次与重复导入都测试，不以“第二次快”替代首次体验；慢素材必须报告是哪类回退及原因。真实样本只在本地使用，记录去标识化。

### 正确性与边界
- 覆盖 CFR/VFR、B 帧、长 GOP、超过 100k 样本、非零起点/edit list、无音轨/单轨/多轨、音频前导延迟与间隙、HDR、旋转、非方形像素、不支持解码及损坏素材。
- 快路径与旧严格路径/FFmpeg 参照比较首/中/尾部和随机 seek、逐帧、封面 PTS、实际剪点；检查音画同步标记及长播放漂移。无法证明局部映射正确的样本不得留在精确快路径。
- 新增/删除/切换/重叠片段、EOF 加号、键盘拖动、缩放平移、默认/自定义封面、独立裁剪和原画质模式往返均不串状态；至少测试 20 段操作与资源上限。
- 3 个不同时段及 2 个重叠选区导出，逐文件验证 JPEG/内嵌 MP4、音轨、区间、封面与色彩；目标手机抽测识别和播放，不承诺新增机型兼容。
- 验证命名冲突、单段错误继续、全局错误停止、目录对话框取消、编码/封装/发布瞬间取消、关闭/换素材、源文件变动、helper 退出、旧 epoch 晚帧、磁盘不足及缓存清理。已发布文件保留，未完成文件不冒充成品。
