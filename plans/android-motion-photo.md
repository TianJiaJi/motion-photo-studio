# 安卓动态照片工具：需求评估与一期实施计划

## Context
- 目标：生成单个 JPEG + 内嵌视频文件，在指定小米手机的系统相册中识别为动态照片并长按播放；不实现苹果 Live Photo 输出。
- 一期：视频导入/预览/时间轴、画面与时间裁剪、无损模式、帧率/分辨率/CRF、抽帧或自定义封面、合成导出。
- 二期：提取视频/封面/GIF/音频、加音乐、静音、压缩、图片转实况。
- 当前目录主要为样本与参考项目，尚未发现独立的产品代码。已收到四张参考截图：功能首页与编辑器裁剪/参数界面。

## 已发现的证据
- `样本/小米手机实况/` 有 12 个 JPG；已只读检查 XMP/EXIF 与内嵌视频位置和流参数，不仅依据扩展名判断格式。
- `样本/苹果手机实况/` 有 9 组 HEIC/MOV，可作为视频输入/旋转等测试资料，不据此扩展苹果输出范围。
- `样本/参考代码/turn-video-into-live-photo-main/`：React 19 + TypeScript + Vite + FFmpeg WASM；README 声明支持裁剪、压缩、封面、XMP 和小米生成。该声明尚不等于本项目设备验证通过。
- `样本/参考代码/MotionPhotoMaker-main/`：Python + ExifTool 合并工具，GPL-3.0；不能未经许可评估直接复制到闭源产品。
- `filmcraft/` 是大型 Rust 非线性编辑器，不适合作为一期底座；不引入其完整编辑/自研编解码体系。
- 已只读检查全部 12 张小米 JPG：全部仅有新版 `MotionPhoto=1` / `MotionPhotoVersion=1` / `Container:Directory`，未发现 `MicroVideo`；视频项长度与 `文件总长 - ftyp box 起点` 全部吻合，Padding=0。封面时间约 1.244–2.501 秒。尚未证明私有 EXIF 对识别是否必要。
- 例如 `MVIMG_20261004_144929.jpg`：总长 11,490,848 字节，视频起点 6,697,475，视频长度 4,793,373，封面时间 1,531,921 微秒。
- 已通过内存管道调用 ffprobe 检查全部 12 段内嵌视频（未生成临时媒体文件）：均为 H.264 / yuv420p / 1080×1440 + AAC，时长 1.925–3.066 秒；部分带 ±90° display matrix，平均帧率约 18.13–29.02，不能假定全是恒定 30 fps。
- 全部样本 EXIF 的机型为 `Redmi K70E`；ExifIFD 中均有私有 tag `0x8897`，类型 BYTE、数量 1、值 1。参考项目 `createExifData('xiaomi')` 也写入此字段：这是值得优先 A/B 验证的兼容线索，不是已证实的必要条件。EXIF 无法给出当前系统/相册版本。
- 本轮仅探测结构与流参数，未执行完整逐帧解码、生成或真机导入测试。
- 在线调研限制：官方 Android 页直接抓取因网络 fake-IP 安全检查被阻止；Ollama 搜索未登录。其他搜索通道能返回官方规范摘要，但不能把摘要当作已取得的完整原文。

## Approach
- 先验证“可被目标小米相册识别”的最小格式闭环，再建设完整编辑界面。
- 推荐 Windows 桌面版：Web UI + 原生 FFmpeg/ffprobe，完全本地离线；不采用纯浏览器 WASM 作为一期主处理引擎。不设人为时长上限要求避免把完整媒体加载到 UI 内存。
- 将“不重编码快速裁切”与“精确裁切/画面调整转码”分开，不把轻量转码宣传为无损。
- 格式兼容采用有证据的配置方案；双写旧新 XMP 是待验证候选，不能直接承诺覆盖所有 MIUI/HyperOS。

## 最新交互修正（用户后续明确，优先于历史“无损”措辞）
- 原“无损”开关最终定义为**原画质（跟随原片）一键预设**：用户不用手调，允许转码；保持原显示分辨率和帧时序/FPS，音频跟随采样率/声道。自动兼容编码采用高保真质量，明确不是数学无损，也不假称读取了源编码器的原始 CRF。
- PCM16 输入保留 PCM 采样格式/原采样率/声道，只截取选段并验证真实声音样本，不默认有损压成 AAC；其他音轨若重新编码明确披露。关闭预设恢复原手动设置。
- 严格 H.264/AAC 码流复制模块保留用于底层/CLI回归，但不再作为该界面开关的准入门槛；未交付 HEVC 直接复制原型已退出产品路径。以下早期“音视频均不重编码”描述是历史方案，不能覆盖本次用户澄清。
- #20 当前正在回归/打包 0.1.1，新规则未验收前不以旧安装包代替，不提前标 M5 或公开 GitHub 推送。

## 已确认与待确认决策
- 已确认：Windows 电脑优先，完全本地离线，仅当前一台小米设备可测试。
- 已确认：导入与导出不设产品层的人为时长/体积上限；不代表内存、磁盘、编码器或相册没有实际限制。需要流式文件处理、按需缩略图、进度/取消与大文件异常提示。
- 已确认：验收机 Redmi K70E，OS 3.0.304.0.WNLCNXM.C11、Android 16、相册 4.3.1.18；USB 原文件传输。用户已确认带标记可播放、自定义 C/D 封面保持和方向正常，采用 C 为当前设备默认格式；不能把单设备通过推广为全版本兼容。
- 已确认：一期仅视频生成，不支持导入已有实况 JPG 再编辑；输出兼容优先 SDR JPEG/H.264，自定义封面 JPG/PNG，HDR 输入需显式提示转 SDR。
- 已确认：“无损”是原画直出快捷开关。开启时原画优先，暂停画面裁剪/分辨率/帧率/CRF 设置，时间吸附到关键帧并显示实际区间；关闭后恢复之前的编辑设置。

## 产品与技术建议
### 桌面形态
- 推荐 Electron + React/TypeScript + 原生 FFmpeg/ffprobe。相比纯网页，便于离线打包、文件随机读取、长视频处理、任务取消和流式输出；相比在线网页，不需要上传与服务器费用。代价是安装包较大、需要发布更新。
- UI 复用 Web 技术，媒体引擎不使用 FFmpeg WASM；一期不同时交付网页版、macOS/Linux 或手机 App。
- 渲染进程禁用 Node、启用 contextIsolation/sandbox；通过 preload 的类型化 IPC 调用白名单任务。主进程 spawn 使用参数数组、不开 shell，不允许 UI 提交任意 FFmpeg 命令。
- 浏览器不支持的 HEVC 等输入，按需生成本地代理预览；精确抽帧和导出使用原文件，不依赖 HTML video 的 seek 精度。代理/缩略图按需、限缓存、可取消，不预读完整长视频。

### 无损与精度
- UI 保留一个“原画直出（无损）”快捷开关，不要求用户理解复杂编码模式；开启意味着跳过额外画面处理和质量压缩，而不是将 CRF 调成 0。暂停而非删除画面裁剪/分辨率/帧率/CRF 设置，关闭后恢复；预览必须反映当前有效设置。
- 默认“精确模式”：转码选中片段，允许画面裁剪、分辨率、帧率和 CRF；软件 H.264 CRF 为一期稳定基线。
- “无损模式”明确为“音视频流不重编码”：仅对兼容编码启用，关键帧/可独立解码 GOP 边界吸附，显示请求区间与实际区间。时间戳/容器可重写，并非整个文件字节完全相同；JPEG 封面也可能编码。
- 无损时禁用画面裁剪、缩放、帧率和 CRF。编码、色彩（如 HDR）或音轨不符合已验证 profile 时说明原因，须用户切换精确模式，不静默转码。封面选择仍可使用，但不把“无损”承诺延伸到 JPEG 封面。音频包边界与视频边界不同，需校验实际音画起止。
- 不做首尾重编码、中间复制的 smart rendering：它不是真正全程无损，且跨 GOP/B 帧/编码参数拼接复杂，不纳入一期。
- 时间输入/显示到毫秒，内部用整数时间戳与流 time_base；实际视频剪点只能落到帧边界（30 fps 约 33.3 ms），不能承诺任意 1 ms 都对应独立画面。封面抽帧使用实际呈现时间，剪辑后重新映射到输出时间轴。

### 格式兼容
- 规范基线：JPEG 主图 + 尾部 MP4；新版 MotionPhoto 与 Container Directory 为主。
- 兼容候选：在同一 XMP 中双写 MicroVideo 和 MotionPhoto，而不是插入相互冲突的重复 XMP；旧版 offset 是从 EOF 到视频起点的距离，在无尾部额外数据的简单封装中等于 MP4 字节长度。
- 优先对照四种输出：新版 / 新旧双写，各自有无 `0x8897=1`；相同封面、视频、文件名策略和导入方式，仅改变元数据。
- 未有证据前不复制 OPPO/xhs 所有者、样本设备身份或整段 MakerNote；小米私有标志按测试结果进入独立 profile。不会通过伪造拍摄机型来宣称兼容。
- 默认兼容视频 H.264 8-bit yuv420p + AAC（原片无声则不强制加音轨）；不把参考模板中旧长度/时间戳直接用于新文件。
- 先处理视频到临时 MP4 → 确定最终字节长度和封面时间 → 写入正确 JPEG APP1/XMP → 流式追加 MP4 → 结构验证 → 原子发布最终文件。
- 封装采用 JPEG marker/segment 解析与 MP4 box 边界校验，不用全文字符串搜索 `ftyp` 作为唯一定位方法；XMP 按命名空间处理，支持属性/元素写法并校验 APP1 长度。生成的封面移除冲突的旧 Motion Photo/MPF/厂商字段，不盲目复制 GPS、设备标识或缩略图偏移。
- 默认命名 `MVIMG_时间戳_唯一后缀.jpg`，只作为便捷策略而非格式保证；计数/文件偏移禁止 32-bit 位运算截断，大文件采用 64 位语义和分块 I/O。
- 双写能提供旧读取器兼容机会，但不能证明覆盖所有 MIUI/HyperOS；一期仅承诺已实测的单机型/系统/相册组合。需补旧系统设备后才能扩大承诺。

### 封面与参数交互
- 从源视频任意位置抽帧或选择 JPG/PNG；视频帧精确落到实际呈现帧，并经过当前有效方向/裁剪/色彩处理。若抽帧不在最终片段内，与自定义图一样视为无对应视频帧的封面。
- 有对应帧时写入输出片段内的微秒时间戳，新旧字段一致且允许合法的 0；无对应帧时采用规范的未指定语义（候选 `-1`，PoC 复核原文并实测相册）。不冒称任意上传图就是视频第 0 帧；若相册不接受未指定值，需在 PoC 阶段重新确认交互，而不是悄悄替换封面。
- 自定义封面与输出画面比例不同时提供裁剪或留边预览，不拉伸；PNG 透明区显式合成背景，输出标准 JPEG、正确 Orientation 与 sRGB。封面属于单独图像链路，不改变原画模式的视频码流。
- 普通模式建议默认 H.264 / 30 fps / CRF 23 / 1080 档不放大，提供原分辨率与其他档位；显示最终宽×高以消除竖屏“720P/1080P”歧义，编码尺寸对齐要求要在预览中可见。
- 默认保留原音轨；普通模式必要时转 AAC，原片无声则无音轨。独立静音、加音乐和音轨编辑入口仍属于二期。

### 一期边界与工作量初估
- 保留用户列出全部核心功能；补充参数联动、旋转/色彩处理、导出进度/取消、错误诊断、临时文件清理、无损实际剪点和真机验收，属于完成核心流程必需工作。
- 不设人为导入/导出时长与大小上限；超大文件受磁盘、文件系统和目标相册实际能力约束，提示风险但不自动截短或偷偷压缩。长实况能生成不代表小米相册必然完整播放。
- 一期按单视频编辑、单任务导出；不扩展多轨、批量、已有实况导入编辑、音乐、GIF 或 AI 图片动画。常见 MP4/MOV/MKV 等容器以所捆绑 FFmpeg 的实际解码能力为准，扩展名不等于编码支持。
- 二期沿用媒体处理和封装模块：视频/封面提取可直接复用解封装；GIF/音频/静音/压缩/加音乐增加独立任务；图片转实况需再明确是静止视频、平移缩放动画还是 AI 动态，不默认包含 AI。
- 按 1 名熟悉 Electron/FFmpeg 的全职开发者估算：兼容 PoC 3–5 人日；桌面基础/离线打包 2–3；导入/预览/时间轴 4–6；裁剪/封面/参数 5–7；转码/无损/封装/任务治理 5–7；回归/真机/发布 4–6；合计 23–34 人日，另预留约 20% 风险，即约 6–8 个工作周。真机反馈等待不含在有效人日内。
- 格式 PoC 应为独立第一里程碑，未通过则暂停全量 UI 建设、定位私有元数据/相册索引问题，而非继续承诺交付兼容性。

## Reuse
- `样本/参考代码/turn-video-into-live-photo-main/package.json`：现有 UI 与媒体依赖可作为技术选型依据。
- 参考 Web 项目根目录 `LISENSE` 为 MIT，复用代码需保留版权声明，并核查其引用算法的上游许可。
- `src/lib/extractmotion.ts`：`extractMotion` / `createMotion` / `embedXMP` / `createExifData` 提供解析、封装、APP1、厂商 EXIF 的思路；不能原样作为生产实现。其全文件 FileReader/字符串解码不适合大素材，且已有 MPF/重复 XMP 风险 TODO。
- `src/lib/extractutil.ts`：`XmpStrings` 有新版/旧版双写模板；`fixXmpString` 用正则修改长度与时间戳，但不更新 MicroVideo 时间戳，且 `if (stamp)` 会跳过合法的 0。应改为命名空间感知解析与统一序列化，长度/时间戳单一来源。
- `src/App.tsx` 的 `ffexec`：可参考 crop/scale/transpose、libx264、抽帧与进度交互；原生执行器需独立实现，不能保留 WASM 全文件读写或不受控命令输入。
- `src/components/cropper.tsx` 的 `MyCropper`：可参考比例按钮、像素坐标回调和旋转映射，但当前仅提供固定比例，不满足任意自由拖框，需补充自由裁剪交互。不引入 Apple LivePhotosKit、上传 API、Cloudflare worker 或在线统计。

## Verification
### 自动化与本地回归（拟新增脚本）
- `npm run typecheck`、`npm run lint`、`npm run test:unit`：类型、静态检查、XMP 命名空间与属性/元素写法、合法 0/未指定时间、双写一致性、JPEG APP1 长度、冲突/损坏元数据、超过 4 GiB 的偏移计算。
- `npm run test:integration`：生成小型可控媒体，导出后独立提取 MP4，ffprobe 校验时长/方向/音轨并用 FFmpeg 完整解码；正常转码剪点误差以相邻实际帧时间衡量，不以固定毫秒宣传。
- 原画路径：确认没有视频滤镜/重编码、保留分辨率和帧率；比较所选有效压缩包或规范化后的码流（考虑容器/bitstream filter 的表示差异），并验证首尾能解码、无黑帧花屏、音画同步。不能只靠参数里出现 `-c copy` 就算通过。
- `npm run test:e2e`：导入→裁剪→换封面→原画开关暂停/恢复→导出/取消；断言实际区间与参数禁用状态、不会误提交暂停的滤镜。
- 样本用于回归与格式读测试，不修改原文件；生成内容统一进入测试工作目录。原始私人照片不随发布包分发。

### 大文件、长时长与鲁棒性
- 覆盖至少 2 小时长输入、超过 4 GiB 的输入与实际封装输出、中文/空格路径、可变帧率、B 帧/开放 GOP、±90°旋转、无声/多音轨、HDR 转 SDR、透明 PNG 与异常文件。
- 以上是测试点，不是导入/导出产品上限；对 3 秒、15 秒、1 分钟、10 分钟及更长输出记录相册识别和完整播放结果，不推断“短片成功→任意长度成功”。
- 观察 UI 响应、取消响应、内存与临时磁盘占用；内存不得按整段媒体字节大小线性增长。模拟磁盘不足、FFmpeg 失败、目标文件被占用、源文件变更与应用重启，确认原文件未改动、临时残留可清理。

### 真机与离线验收
- 记录机型、系统、相册版本、测试文件哈希、profile、编码、时长和结果；通过 USB/原文件传输，避免聊天软件转码，检查传输前后内容一致。每组使用唯一文件名避免相册缓存干扰。
- 检查动态照片标识、长按完整播放、封面正确、方向/画面一致、声音正常、退出相册再打开仍可识别；出现失败先区分元数据、编码、文件传输和媒体索引。
- 断开网络，在无 Node/FFmpeg 开发环境的 Windows 电脑安装并完成全流程；不依赖 CDN、远程字体、在线统计或自动下载运行时组件。
- **不能用浏览器预览成功、桌面播放器播放成功或 XMP 字段齐全代替小米相册验收。** 当前没有旧系统设备，兼容表必须保留“旧系统未验证”。

## 风险与发布前置条件
- **格式风险：** 现有样本证明一种原生文件结构，不证明字段必要性。若四组对照都失败，继续比对厂商 EXIF/相册索引和已知可用输出，重新评估范围与工期。
- **长度风险：** 软件不做时长上限，但小米相册实际可能拒绝、截断或无法流畅播放长文件；如发生必须报告真实限制，不能将无法控制的相册能力作为软件保证。
- **原画风险：** 原片 HDR/HEVC/特殊音轨可能不符合一期兼容 profile；应禁用原画并解释原因，不用“高质量转码”冒充不重编码。
- **许可风险：** 本机 FFmpeg 是含 GPL 组件的完整构建，不直接当作发布包；采用 libx264 的发行构建需要履行相应许可与源码提供义务。参考 MIT 项目保留声明，GPL Python 项目仅作行为参考。发布前审查全部依赖/二进制许可；闭源/商业发行另做合规确认，调用独立进程不是豁免理由。
- **交付边界：** 估算不含付费签名证书购买、旧系统新增设备适配、苹果输出、云端服务、二期功能或无限硬件性能保证。
