# 缓存清理与恢复记录

应用缓存与原片、成品分开管理。默认用户数据目录为 `%APPDATA%\Motion Photo Studio`；设置 `MOTION_USER_DATA_DIR` 的测试或部署使用其指定目录。

## 当前启动/退出策略

用户已明确授权丢弃应用专用 `jobs` / `media-sessions` 中的旧任务缓存，包括缺少或损坏标记的历史 `job-UUID` 目录。启动接收新任务前执行清理，退出时在任务、helper 和资源读流全部排空后再清理；失败留待下次启动重试，新会话总是新建 UUID，不恢复旧内容。编辑页不再显示黄色历史横幅，异常路径/占用记录只在帮助中查看。

此显式重置仅限两个应用工作区，完整预检树后按目录/文件身份删除；不跟随 symlink/junction，拒绝硬链接及超预算遍历，不批量删除用户数据目录，也不涉及原片和已发布成品。发布恢复仍使用独立严格的所有权协议。以下运行中任务删除规则仍保留；启动重置是明确授权的独立入口，不为旧目录伪造标记。

## 顺序与所有权

1. 停止相关任务和原生预览，确认辅助进程退出、索引关闭。
2. 撤销资源令牌，停止新读流，销毁现存读流并等待实际 `close`。等待有时限；超时不授权删除。
3. 校验缓存根目录、job 目录和所有权标记，检查整个待清理目录树。不跟随符号链接/junction，也不递归删除未知根路径。
4. 同步写入独立恢复记录，然后删除内容，最后删除 `.owner.json` 和空目录。
5. 只有整个目录删除后才移除恢复记录。

`jobs.cleanup-journal` 和 `media-sessions.cleanup-journal` 位于对应缓存根目录旁边。记录绑定根路径、根目录身份、job ID 和 job 目录身份，不接受任意文件路径。中断后只可恢复相同的已授权目录。

若所有权标记已经消失，恢复记录也**只允许删除同一身份的空目录**。出现任何意外内容都拒绝清理。常规运行中的删除不能认领无记录的无标记目录；仅上述显式启动/退出工作区重置可以丢弃历史任务。现有有效 v1 标记仍可校验和清理。

路径和身份检查会拒绝检测到的替换，但不是针对拥有本机文件写权限、持续竞态替换目录的攻击者的完整操作系统沙箱。

## 查看原因

编辑页不再显示缓存横幅。打开“帮助与检查 → 缓存恢复记录”可查看目录标识与分类：

- **缺少标记**：运行中删除拒绝认领；下次启动按上述工作区重置规则丢弃。
- **标记损坏或不匹配**：运行中不删除；启动时仅对应用专用工作区重新预检清理。
- **占用**：有限重试后仍无法释放，保留标记或恢复记录。
- **权限**：文件系统拒绝操作，保留恢复信息。
- **异常路径**：目录被替换、含链接或不支持的内容，拒绝删除。
- **恢复记录异常**：根/目录身份不匹配、记录损坏等，拒绝认领。
- **文件系统错误**：操作尚未完成，不当作成功。

当前任务清理失败仍会显著提示。启动时的历史残留不应反复覆盖编辑工作区。

## 人工核查

1. 先关闭素材和应用；若其他程序正在使用这些缓存，关闭相关预览程序后重启应用，让它重试已授权的清理。
2. 按界面显示的区域和 job ID 定位目录；若目录已经不存在，可检查对应 `*.cleanup-journal` 中的同名 JSON 记录。
3. 核对文件用途，确认原片和已保存成品在缓存目录之外且可正常打开。不要凭文件扩展名判断所有权。
4. 两个应用专用工作区内的旧 job 目录按已授权策略重试清理；其他位置的未知内容仍须单独确认。遇到异常路径不要扩大清理范围，不要批量删除用户数据目录，也不要手工补造归属标记。

先前调查的缺标记旧缓存曾按保守策略保留；现用户已明确授权清除两个应用专用工作区中的历史任务，按新策略在启动时处理。自动化验证仍使用隔离目录，不拿原片或成品作删除测试。
