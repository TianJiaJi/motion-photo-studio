# 容器样本索引：当前实现与接入边界

状态：独立基础模块，尚未替代生产 `prepareNativeMedia`，也没有取消现有全片时间核验。原计划第10步未完成。

## 已实现的接口边界

- `app/src/main/media/mp4-sample-index.ts` 只读顶层盒及 `moov`；不读取 `mdat` 媒体负载，不启动媒体工具。
- 返回原始媒体时间基中的 DTS、PTS、持续时间、容器同步样本标记、字节范围、decode index、chunk index、track ID；编辑列表保留原始整数。
- **样本 ≠ FFprobe 包 ≠ 解码后的展示帧。** 同步样本标记也不是对开放 GOP、CRA 或所有输出帧的解码验证。
- `selectMp4Track` 只接受显式容器 track ID，并验证 handler。`probe.ts` 新读取 `stream.id`；不能把流序号、轨道排序、相同采样率/时长作为身份。
- 变量大小样本采用有界前缀数组；固定大小样本采用整数乘法计算偏移，不逐 PCM 样本分配或遍历。
- 默认元数据上限32MiB、额外索引计费上限32MiB、变量大小样本合计100万、固定大小逻辑样本合计最多32位无符号计数范围。索引计费包含对象保守计费，不等于进程总内存或 V8 实测堆大小。
- 表处理分批让出事件循环，再检查取消；mdat 范围查询为二分查找，不执行“每个 chunk 遍历所有 mdat”。源句柄打开前后及解析结束核对身份，最终关闭句柄。
- 当前不支持分片、外部引用、多 sample description、加密/compact sample table、非单位编辑速率等。复用的顶层检查要求 `ftyp`，故不能宣称覆盖所有历史 QuickTime 文件。读取 `ipcm` 样本表不表示原生音频解码已支持它。

## 真实素材失败及修正依据

保留 `artifacts/native-preview/container-index-1792822516611/` 和 `b9dc7a110`：128项单元和2项集成通过，但真实素材只有4K案例通过。

1. 两份素材的音频为 `ipcm`。只读检查发现固定大小4字节，分别有5,000,192与4,727,808个逻辑样本；stts只有一个 run。原实现不仅缺少该条目，还会错误地为每个 PCM 样本分配前缀索引。现改为常量空间固定大小路径，仍保留计数/范围限制。
2. 短 GOP 素材音轨有7444个 AAC 样本；默认 FFprobe 只输出7443个包。单独运行固定工具的 `-ignore_editlist 1` 得到全部7444个，末包位置769267796、PTS7621632。
   - movie timescale = 90000，audio timescale = 48000。
   - edit duration = 14290500，media time = 0。
   - 精确编辑终点 = 14290500 × 48000 / 90000 = **7621600**。
   - 最后包起点7621632已超过编辑终点32个采样时刻；上一包7620608仍在范围内。
   - 这是原始存储与编辑呈现的区别，不能删掉原始样本或无条件容忍“少一个”。

新诊断适配器 `app/scripts/lib/mp4-index-oracle.ts` 分开验证：

- 原始包视图：关闭 edit list，核对完整原始样本数、位置、大小、PTS、DTS、duration、sync。
- PCM：一个 demux 包可能包含多个固定大小样本，按字节/时间跨度核对，而不是强制一包一样本；当前适配器对跨 chunk 重打包明确报不支持。
- 编辑视图：根据已验证原始包起点与精确 edit 终点计算应保留的前缀；再逐包核对默认 FFprobe 的位置/时间/数量。缺中间包、重排序、未解释的数量差异仍失败。
- 适配器当前只覆盖一个媒体编辑段及可精确换算的前导空编辑；跨结束边界重排序、多个媒体编辑段等不能伪装成支持。
- 用生成的 AAC 夹具缩短音轨 edit list，验证“原始完整、编辑后裁尾”两个独立数量断言；真实源文件不修改。

这仍是**离线样本表/包对照**，不证明解码输出帧、音频去 priming、最终 PCM 裁剪或物理音画同步。

## 进入生产快路径前仍须完成

1. 确定原生直接 MFT 输入契约：明确 selected track ID、配置数据、源句柄身份、压缩样本字节范围、整数时间基；不能只删掉 `mapNative` 的 await。
2. 验证 input/output backpressure、`NOTACCEPTING`、stream change、drain/flush、B帧及开放 GOP/CRA、seek preroll、遗漏/重复输出。容器样本只有解码后才获得“实际展示帧”确认。
3. 分离容器时间、编辑呈现时间、原始整数 PTS 和 MF 100ns 时钟。所有转换明确舍入/溢出/精度条件；不能用平均帧率或单个猜测偏移补齐身份。
4. 验证音频按所选轨道按需准备、priming、空段/间隙/末尾裁剪、设备时钟及退出 join。不能把每个压缩音频包等同于固定数量已展示 PCM。
5. 新资源纳入现有所有权、撤销/释放屏障、marker-last 清理；保留当前失败重试与源文件不可变约束。
6. 建立 pending/verified/failed 的能力边界。首帧就绪不代表整片每个定位/封面操作已经核验；区域操作须经原生实际输出确认，失败不能在编辑期间偷偷启动 FFprobe/FFmpeg。
7. 完整回归、新唯一包和相同真实素材首帧/可播放测量。只有容器索引耗时下降，不能称为导入性能验收完成。
