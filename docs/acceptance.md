## 第一轮：5 张

运行 `app/` 下的 `npm run fixtures:compat` 后，打开输出的 `artifacts/m0/compat-*/README.md`。

1. 用 USB 原文件复制，将 `phone-kit/` 根目录的原生对照和 `00_native_video_frame0/` 下四张文件复制到手机 `DCIM/MotionPhotoTest_<runId>/`。
2. **不要**通过微信/QQ普通发图，不要在图片编辑器里另存为；这些操作可能删除尾部视频或 XMP。
3. 等待相册索引后重新打开相册。原生对照应能长按播放；若不能，先检查传输/索引，不直接判定四组失败。
4. 对每张记录：是否有动态标识、长按能否完整播放、封面是否正确、方向是否正确、声音是否正常、重开相册后是否仍正常。
5. 可先用以下格式回复：

```text
系统版本：
相册版本：
runId：
原生对照：通过 / 不通过
A（新版）：
B（双写）：
C（新版 + 私有标志）：
D（双写 + 私有标志）：
异常现象：
```

## 第二轮：覆盖场景

第一轮有成功候选后，测试 `01–08`，或先只测试每组中成功候选的那一张；如要比较 profile 是否完全等效，应测完整四组。

- 横屏/竖屏：内容不倒置、不侧躺、不拉伸。
- 带声/无声：播放应与对应目录名一致。
- 抽帧封面：带声合成视频取 1 秒，静音场景取 0 秒；封面正常、切到视频时不显示黑帧。
- 自定义封面：静止显示蓝底黄方块，长按切换到测试动画是预期结果；不能自动改成某个视频帧。
- 原生视频 00 组：封面为视频首帧，与阳性对照原始拍摄封面不同，这是设计如此。

`phone-results.csv` 可填写 pass/fail，备注里注明“能识别但不能播放”“只有声音”“旋转错误”等，而非统一写失败。

## 不算完成的情况

- 电脑浏览器/FFmpeg 能打开，但未在小米相册测试。
- 只看到动态标志，没有验证长按播放。
- 只测试一张文件，却宣称全部封面/音轨/横竖屏通过。
- 没有记录系统和相册版本。
- 把当前设备的通过结论推广到旧 MIUI/其他 HyperOS。

通过真机测试且完成规范复核后，再记录最小可用 profile 并标记 M0 完成。
