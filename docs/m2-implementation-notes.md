# M2 实施与验证记录（已完成）

M1 已完成并保留独立内部安装包。M2 媒体核心和真实桌面回归已通过，计划第 3 步已标记完成。当前支持导入与编辑预览；实际双路径媒体导出和实况合成仍分别属于 M3/M4，不提前宣称可用。

## 已编写的底层模块

- `app/src/shared/editor.ts`：整数微秒/毫秒输入与显示、分数时间基准、裁剪到偶数像素、截取区间及参数验证。
- `app/src/shared/media.ts`：媒体、预览、原生帧、缩略图与封面描述，不携带本地源路径。
- `app/src/main/media/info.ts`：读取时长/PTS 时间基准、旋转和 SAR 显示尺寸，识别 HDR 与原文件预览候选。
- `app/src/main/media/range.ts`、`resources.ts`：随机令牌资源 URL、64 位安全单范围读取、64 KiB 背压流、撤销/来源变更拒绝、GET/HEAD；不把视频读成 Buffer/Blob，也不允许 renderer 指定任意本地路径。
- `app/src/main/media/frame.ts`：原生准确抽帧、PTS 游标前后步进、显示方向/SAR 归一化。后退使用流式 trim + 覆盖私有临时 JPEG，不使用整段 reverse 内存缓存；前进使用 PTS 严格边界，不能用“当前秒数 + 1/fps”冒充 VFR 逐帧。
- `probe.ts` 保留旧调用兼容，增加显式工具路径/取消信号及时间元数据；协议白名单限制 file/pipe。

底层回归 `b52cc801e` 已退出 0：43 项单元测试、7 项媒体集成全部通过。首次测试发现的空帧 JPEG 初始化与旧旋转样本参数问题已修复；微秒边界、CFR/VFR 前后逐帧、尾帧覆盖区间、越界残留文件及旋转显示尺寸均已通过实测。

## M2 验收检查项（不能只凭代码存在判定通过）

1. 媒体会话管理：原生打开文件对话框、源文件快照检查、私有会话目录、latest-wins 取消、有限缓存与退出清理。各会话只在探测成功后替换当前素材，取消选文件不清空原编辑内容。
2. 独立 `media://asset/<uuid>` 协议和严格 IPC；更新 CSP/请求拦截仅放行该本地资源，不放开任意 file:// 或网络。
3. 原文件兼容时直接范围预览；否则按当前位置生成短窗口低分辨率代理，不能为长片导入先完整转码。窗口长度只是预览策略，不是输入或输出时长限制；HDR 转 SDR 须显式同意。
4. 缩略图按时间轴视口按需生成，受控数量/并发及磁盘缓存；源长片不做全帧索引或全量缩略图预生成。
5. React 编辑区：文件导入、播放器、缩放/平移时间轴、毫秒区间、真实逐帧、原比例/自由拖选。裁剪坐标相对实际可见画面区域，不能把播放器留黑部分当作画面；归一化坐标映射到旋转/SAR 归一化后的源像素。
6. 抽帧/上传 JPG、PNG 封面；已选封面应固定独立资源，不能随预览帧缓存淘汰。自定义封面展示裁切/留边策略，不应拉伸失真。
7. FPS/分辨率/CRF/音轨面板、端到端导入与编辑验证。导出操作在 M3/M4 接入，M2 不提供伪成功导出按钮。

M5 仍负责真实大文件/长片压力、最终手机与干净离线安装验收；目前范围算术测试不等于已测试真实大于 4 GiB 的视频。
