# 0.1.2 启动/导入/连续预览修正（验证中）

用户连续反馈：启动后导入按钮灰一会、读取视频慢、播放每一段结束都停在“准备本地预览”。本轮只做本机修正，不恢复已暂停的公开发布；M5不因此标记完成。

## 原因

- 启动每次需要核对约430MiB原生引擎及实际版本，旧界面仅底栏小字提示，主按钮无原因说明。校验原先在页面加载之后才开始。
- HEVC等非直接浏览器预览格式需要CPU生成有界兼容代理。原先首次就生成12秒，画面先全尺寸归一化再缩小，FPS输出丢帧在较昂贵转换之后；缩略图同时争用解码/磁盘。
- 旧流程只保存一个窗口，播到尾部才生成下一段；不是原文件损坏，也不是导出被切成这些小段。

## 修改

- 保留每次完整引擎哈希/版本校验及主进程门禁；与页面首次加载并行，报告清单/具体引擎校验/可运行检查阶段。界面显著说明等待原因，按钮显示“正在准备引擎…”，就绪自动启用，错误不无限转圈。没有按文件时间戳跳过哈希，也不提供虚假的百分比/固定秒数。
- 首个代理仅3秒，后续仍最多12秒（通常2秒预滚）。预览先降到30fps再做耗时色彩/缩放，直接缩到预览尺寸，预览编码用ultrafast；原始精确帧、封面、导出参数不走此优化。缩略图只在预览/下一段已有准备后加载。
- 最多保留两个代理窗口，第三个请求淘汰最久未用者。后台提前生成下一段并用第二个暂停video元素预载；切换时按URL key提升同一DOM元素，避免段尾重新启动转码和重新从零加载。缓存不扩成全片代理，不对源时长加上限。
- 预取是可选boolean IPC，不携带路径/命令，不能取消前台精确帧/导出/保存；前台活动中拒绝投机预取。切换源、取消和退出仍由会话任务/拥有者清理。
- 原生窗口拒绝网页标题覆盖版本，补上此前#21持久修正。
