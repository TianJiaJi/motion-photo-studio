# MOV 呈现时长与索引边界

## 问题

部分带 B 帧的 MOV，其 FFprobe `duration_ts`/媒体头时长短于最后一个呈现帧的结束时间。原先将该时长作为索引的严格上界，会把有效末帧判为 `FRAME_INDEX`（源帧时间范围/顺序无法建立唯一索引），即使 PTS 严格递增且文件可正常解码。

本地问题素材的去标识化结果：1920×1080 H.264、816 帧、时间基 1/15360；探测时长 208896 ticks，末帧 PTS 也为 208896、持续 256 ticks。MOV 编辑列表允许约 13.617 秒的内容，实际呈现结束是 209152 ticks，即约 13.616667 秒，而非原先的 13.600 秒。

## 处理

`app/src/main/media/presentation-duration.ts` 使用已有的只读 MP4/MOV 样本表解析器，按真实样本 PTS + duration 计算呈现结束，不依据平均 FPS 猜测：

- 仅对可验证轨道 ID、匹配时间基和起点的 AVC/HEVC 轨道进行修正。
- 支持无编辑列表、单段正常速率媒体编辑，以及其前面的整数 tick 空白延迟；复杂编辑保持原有路径。
- 仅在样本解码时长恒定时使用此尾部证明；重排 VFR 的混合 stts 时长不能直接当作呈现保持时长，保留原声明范围，避免把拷贝输出多算一帧。
- 所有样本必须完整位于编辑范围内；不恢复被编辑列表裁去的帧，不向外舍入编辑边界。
- 只延长明确低报的时长，不缩短时长、不改 PTS、不丢帧、不改原文件。
- 使用现有元数据/内存预算，最多遍历 100000 个视频样本，并定期让出事件循环、检查取消。
- 常规探测与直拷贝导出探测共用修正，确保 UI、索引、封面和导出使用一致的末端边界。
- 容器时长修正不等于帧身份核验。原修复版本仍执行完整原生映射；当前快速导入工作树采用有界启动核对与局部精确源 PTS 核验，严格路径保留完整检查。

不支持的容器元数据继续使用既有探测结果。这不是对所有损坏文件、复杂 edit list 或时间戳异常的通用修复。

## 验证

问题原文件已通过导入和原生映射（816 帧，视频无需兼容转码），首/中/末帧定位返回正确索引；全长导出规划保留末帧 PTS 208896，结束 PTS 为 209152，源文件 SHA-256 未变。音轨独立走现有 PCM 兼容准备路径。

原文件的实际原画质预设导出也已验证：1920×1080、816 个可解码视频帧、时长 13616666 微秒、末帧封面时间 13600000 微秒，保留双声道 48000 Hz AAC 音轨，原文件 SHA-256 未变；验证输出仅存于测试临时目录并在结束后删除。

最终验证：类型检查通过，136 项单元测试及 21 项相关集成测试全部通过（涵盖原生导入、会话、MOV 回归、容器样本索引、精确剪点和视频编码导出）。未运行全量集成套件或桌面 UI 自动化。

后续快速导入全量回归发现 VFR 拷贝输出的混合 stts 时长被误当成尾部保持，导致范围从 33280 扩展到 33792 ticks。新增上述保守限制后，`b2a8ca904` 的 160 单元与 17 项定向集成通过，既有 MOV 尾帧保护和 VFR 无重编码包/时序校验同时保留。此补充不改原始问题素材或上述历史证据。

回归用例不包含私人素材：`app/tests/integration/mov-presentation-duration.test.ts` 生成 MOV，只缩短其媒体头时长，保留样本与编辑列表，验证旧边界会报错、新路径保留末帧，并检查实际导出帧数及末帧封面时间。边界与编辑列表保护见 `app/tests/unit/presentation-duration.test.ts`。
