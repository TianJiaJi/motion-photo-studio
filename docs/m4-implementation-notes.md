## 发布后端与桌面接入

- `motion/publish.ts` 接受已经过 M3 验证的私有 MP4/JPEG 和关联时间，不允许 renderer 传 profile、原生路径或 XMP。
- 沿用 M0 `C-modern-xiaomi` 与流式 mux。新文件先落在目标目录的独立工作区，回读新版 XMP、EXIF、视频长度、无 padding/无尾随数据及关联时间。
- `hash-jpeg.ts` 对 JPEG 除有意替换/剥离元数据外的全部保留字节作流式 SHA-256，包含压缩图像扫描、ICC、JFIF/Adobe 与 EOI；与源 JPEG 一致。MP4 对照整个私有视频与成品视频区间 SHA-256。它们使 M3 的真实解码验证传递到新容器，不以纯 box 结构检查冒充解码证明。
- 发布前复查原片/上传封面/私有草稿指纹，并确认时间戳处于输出时长内。最终同卷 hard link 是原子可见的提交点；目标已存在必然失败，不覆盖、不删除，也不回退 rename-overwrite。
- 提交前取消不生成成品；提交后即使取消信号到达也返回“已保存”。提交后的清理失败返回已保存及警告，不能返回误导性的“取消”并让用户重复生成。桌面取消收据协议已接入并验证。
- `jobs/publications.ts` 在应用私有目录保存同步写入的意图记录，在输出目录创建唯一 `.motion-photo-job-UUID` 工作区。重启恢复只清理合法 owner、固定文件名/模式、非符号链接且无未知内容的工作区；从不记录供清理使用的最终输出路径或源路径，从不递归删除未知目录。
- 输出目录移动/目标盘离线/临时文件占用或所有权不明时保留记录、发出集中警告，下次启动重试；不为了清理而删除用户文件。没有声称断电耐久性：文件 sync 与原子可见性不等于跨文件系统/硬件的断电保证。
- 可用空间使用 statfs 检查当前可读容量；无法查询时保留警告并捕获真实写入失败。空间、锁、不支持硬链接、回读失败使用明确公共错误，不泄露原生路径。生产不会利用测试注入接口替换文件系统行为。
- 流式复制新增实际字节进度；JPEG 扫描、哈希支持取消，不设置产品时长/体积上限。
